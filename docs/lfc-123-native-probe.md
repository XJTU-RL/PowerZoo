# IEEE 123 原生配电侧 LFC 探针

此探针只验证配电侧接口，不注册训练环境，不启动 Simulink，也不替代
13 节点或 34 节点论文实现。从仓库根目录，在已安装 OpenDSS 运行时的
环境执行：

```sh
python -m unittest tests.test_lfc_123_native
python -m scripts.check_lfc_123_native
```

- 馈线复用 `node_systems/123Bus/network.dss`，与
  `configs/systems/123Bus.yaml` 的馈线入口一致。配电模型未复制入新目录，
  实际求解只改独立的引擎临时副本。
- `scenarios/lfc/ieee123-native/probe_v1.json` 单独记录版本、设备和相别、
  秒级时钟、始点 P/Q 算术样例和固定储能请求。原生调压只在零时刻完成，
  后续固定档位。负荷为静态铭牌模型，不播放 OEDI 或其他 15 分钟曲线。
- 四台储能必须能按设备名、母线、相别、接线、kV、kW/kWh 对齐原生对象。
  读写按 1 秒区间进行，正 kW 表示向电网放电，负 kW 表示充电；原生端口
  功率转换符号后再记为注入。每段只完成一次原生能量和时钟积分。
- 等值输电负荷为 `目标起点 + (当前馈线净输入 − 馈线起点净输入)`，
  无隐式倍率，P/Q 分别以 kW/kvar 输出。100,000 kW / 35,000 kvar
  仅为验证算术和符号的输入；未校准 Simulink 工作点，也不声明输电频率响应。
  真正接入前应先用已验证的输电侧初值替换该样例，并核实时钟、功率换算和
  输电到配电侧有无反馈。
- 报告包含原生源端和负荷端 P/Q、网损、实测储能注入和 SOC，以及场景与
  实际消费的馈线哈希。两次相同的复位回放必须完全一致。储能功率、能量、
  时间及有功闭合通过后才输出成功；这不是长期跑分或电压、热限合规证明。
